# P3 运行基础与验证

日期：2026 年 10 月 19 日。状态：已实现运行基础。设计依据为 [P1](./11-P1游戏体验与交互规则.md)、[P2 玩法矩阵](./12-P2三十关玩法设计.md) 和 [首章规格](./13-P2首章三关交互规格.md)。

## 现在可以体验什么

刷新正式网站，点击顶栏“三岛邮路”，或从探索手记进入：

1. 五章货单列出各自三项主线与三项可选委托，可直接去任何现场。
2. 现有关卡有效完成后，成果归档并显示已有读数；第一次操作或仅访问不会生成成果。
3. 三项主线齐备且前章已交付，才开放本章共同交付。回条可以回看，交付不会重复结算。
4. 提前完成的成果直接使用；十五项主线即可完成五章交付，不查三星、支线或阅读时长。
5. 重做保留有效成果、地图复色和历史最佳。新一轮开始前，已有正式尝试进入历史，可从货单回看。
6. 没有原始数据的旧完成记录显示完成事实，不补造参数、仪器、对照或失败过程。

这是可操作的邮路基础界面。现有三十关仍使用原有实验规则和开场；P4 再把 P01、C01、M03 的新版操作、人物演出、原点换算与交付演出接到这一基础上。当前回条是文本留存，地图三站航行动画与邮局生活布景按后续阶段制作。

## 保存边界

新增内容分别存成按 ID 索引的表，方便不同关卡的跨页更新独立合并。

| 表 | 内容 | 约束 |
|---|---|---|
| `mailArtifacts` | 每关有效成果、来源、历史最高星与修订版本 | 本地成果不自动等于章节送达；原版本引用保留 |
| `mailDeliveries` | 每章一次交付及当时引用的成果版本 | 章节依次交付；回看与成果修订不再发一次奖 |
| `mailFacts` | 访问、首份成果、交付和正式桌位等事实 | 与研究分数分开；访问不授予成果 |
| `researchRuns` | 新规则当前研究 | 一次正式事务对应一条可重放命令 |
| `researchHistory` | 前一轮研究和原规则尝试 | 不能跨轮搬证据拼成新的三星 |

现有 `physicsScenarios`、`mathScenarios`、`chemistryScenarios` 继续保存原关卡。成果提取先调用所属引擎的恢复逻辑，再读取其真实记录。历史完成标记与有效成果相认；一轮新的失败不会覆盖过去的有效页。

更早的物理 `physicsLevels/physicsStories` 与数学 `mathLevels/mathStories`，只接受对应旧模型认得的完整完成标记。已有星级保留；没有读数便采用中性描述。化学原生旧档继续经既有迁移流程处理。

初始化保存器时使用磁盘原始状态作为合并基线。页面里的规范化和迁移结果因此能够被识别为待写入变化，避免“页面内已迁移，刷新后却没有保存”的问题。

## 新研究接口

新规则名为 `worldline-1`，模型另有版本。它与旧版 scenario 事件分别恢复；历史星级不会因为采用新判据而被重新计算。

### 三个独立判断

- `recordValid`：声明是否由这条记录支持。真实的阴性参考可以有效。
- `goalSupported`：是否支持当前委托目标。有效参考不自动完成目标。
- `quality.verified`：控制比较、交叉取证等额外研究是否按专属规则成立。

旧记录的新版有效性标记为未知，不把旧 `success` 冒充新的三项判断。当前桥接适配器让模型重新计算结果，不从显示文字或调用方传入的“正确”标记评分。

### 正式事务和恢复

命令必须携带本轮 `runId`、唯一 `id` 和 `expectedSequence`。重复命令、旧轮回调、过期序号、越界输入或不兼容模型，在扣费前拒绝。接受后一次性保存输入快照、固定条件、结果、来源、费用、声明和引用。

`quote` 仅预览费用，不改资源。普通记录 2 时间/1 器材；合格补充首次 1/0；工匠首条不耗器材。正式不成立声明扣 1 可靠度，合法参考不扣；相同测量修改身份判断只引用原测量事实，不能生成比较奖励。付费核对资料标为 `given`，不能冒充本人实验。

第一条件有支持后仍停留现场，由 `advance` 主动进入第二条件。`supplement` 与 `return` 在保留主进度的情况下补查已有条件。归档后可以同轮补充并发布修订；旧交付仍引用原送达版本。新开研究保留前轮原稿和已有成果。模型版本变化时保留旧稿，开启空白新轮；恢复不兼容旧稿需要原模型，不能偷偷用新公式重算。

补给最多一次；若仍有可负担的合格比较，就先保留该路径。补给影响本轮第三星，第一、第二星与历史有效成果仍可保留。

### P4 接入方式

1. 为首章实际新参数注册带独立版本的适配器；M03 必须先加入真正的原点转换与代入核对，当前适配器不授予虚构的换原点奖励。
2. 经 `startResearch` 建立新轮；每次动作经 `commitResearch` 事务提交，归档成果自动接到同一份货单。
3. 新舞台读取同一结果快照，局部更新；将现有原规则关卡界面逐关换入新接口。
4. 按 13 的 18 项验收检查新机制，补齐人物短开场、明示新条件和首航演出。

原规则 UI 当前仍按原有费用与判定运行；上节的新规则已实现接口与自动检查，切换到新版三关在 P4 完成。

## 生命周期与界面

实验台销毁后，正式提交、保存回调与开场完成回调不再生效。舞台仍使用已有局部更新机制；原三科实验台的拖动、跨视图只读状态与焦点行为纳入回归。

邮路面板复用现有模态容器，不增加进关前置层级。关闭时释放点击和窗口缩放监听；窄屏自动露出当前章节，关闭按钮保持在标题上方；静音与跳过开头不影响交付状态。

最终执行结果与截图见 [P3 验证记录](../../output/p3-verification.md)。检查包括新规则无失败预算、真实阴性参考、答案修订、跨条件/跨轮引用拒绝、补充核对、成果修订、事件重算、旧模型记录保留、顺序交付、存档冲突和重置。
