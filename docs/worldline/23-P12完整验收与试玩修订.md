日期：2026 年 10 月 21 日。范围是当前三十个研究现场、五章共同交付、结局、追加回条，以及保存和重做边界。

本阶段分为工程验收与真实玩家反馈。自动化和代码审查可以证明流程、状态与模型之间的约束；玩家是否理解、愿不愿继续，必须来自实际试玩。最终工程结果见 [完整验收报告](../../output/release-verification.md) 与 [P12 验证记录](../../output/p12-verification.md)。玩家反馈另存 [试玩记录](./24-P12玩家试玩记录.md)，未收到的部分不填写结论。

## 补上连续主线的缺口

此前各章浏览器回归验证本章实际操作，但通常用原规则完成标记准备前置章节。本阶段增加一个完全空白的浏览器上下文，实际操作十五项新版主线，从四箱货出发，完成五次交付，看到 00 和正式桌位。

连续流程故意只走普通两星路径，不领取补给，不做第三星研究，不做支线，不填写作文；P01 保留一次正式失误，再免费调整恢复。M10 提前到访，拆信前的预测经过刷新后仍保持封存，提前完成也不会跳过前四章。

首航后接夜班、共同改稿、图册与新记录，最后带着真实寄出版本回到邮局。主线结束后再制作 M02 附页，确认阿澜的追加回条独立寄出；重开并失败不会撤回已经收到的五份回条、原有星数或选定的 00。取消重置和确认重置分别验收。

浏览器只通过真实按钮、滑条事件、放置电子对、排列变换卡和实际键盘按住/松开操作，不直接往存档填入新版成果或伪造测量。自动化偶尔实际按得过长时，只能在免费试验区清空重试，不修改短长音阈值或注入时长。

## 本轮修正的实际问题

### 保存失败不能把交付卡在半路

原来研究结果可以在内存里继续积累，但交付演出要求保存成功才打开。存储达到限额时，会出现进度已经改变、玩家却停留在原页的情况。

现在将“当前会话内有效”与“已经写入本地存储”明确区分。保存失败时，研究、五章交付和追加回条仍可继续；顶部持续显示本次会话提示，并给内容留出位置。交付页也改用会话说明，避免声称刷新后还能保留。原有磁盘存档不被内存结果冒充。存储恢复后，下一个保存点会尝试写入当前会话，成功后撤去提示。

跨页冲突仍按原有冲突规则处理，不作为存储不可用而跳过检查。无法保存时仍有刷新丢失风险，界面明确说明，不能承诺断电恢复或云备份。

### 损坏存档不能被自动保存覆盖

原来存储层在原始字符串未变化时信任初始化基线。损坏 JSON 触发页面的回退数据后，自动保存仍可能把它覆盖。

现在每次写入前确认原始记录可解析且版本可识别。普通探索不覆盖损坏记录，取消重置也不改变它。只有玩家通过既有确认框明确重置，才保存一份精确原文到 `knowledge-islands-v2-unreadable`，然后建立可重新加载的新档。备份为一份有界恢复副本，不自动恢复为游戏进度。

### 电键时长使用输入发生的时间

P07 原来用事件处理函数执行时的时钟计算时长，处理延迟可能混入按键时间。现在使用同一单调时钟下的原生事件时间戳；不兼容的时间戳回退到单调时钟。短长音阈值保持原样。测试覆盖处理延迟、重复键、失焦、指针身份和时间戳兼容性，正式纸带仍是玩家实际输入，不从目标码本补造。

### 验收结果不能沿用旧的绿报告

浏览器检查开始时先写入“运行中、未通过”，本次失败会保存失败结果和原因。新增 `npm run verify`，按次序执行全量脚本语法检查、双入口一致性、单元测试和十二组浏览器检查。报码专项串行运行，避免并发浏览器把实际按键拖长。

完整验收同时生成 JSON、Markdown 与各组日志；运行中或失败不会继续保留上一轮“全部通过”的总报告。环境中断后可用 `npm run verify -- --resume` 续跑：先确认代码、资产和测试未变化，再沿用已通过组，未完成或失败组仍重跑；报告逐组标明来源，语法、入口和单元测试重新执行。跨页浏览器检查先切回被观察的标签页，再判断货单更新与旧运行时退出；原有保存内容、冲突和销毁断言继续保留。

## 试玩观察与剩余边界

工程走查确认：首屏有“四箱寄给谁”的任务，主操作可以直接进入现场；参考与正式声明分别显示，错误可恢复；回条读取实际寄出版本，结尾能回到真正的邮局桌位。

这些是可观察的界面与流程事实，不能据此推断陌生玩家一定看懂或觉得有趣。中段图例分歧是否容易理解、手机上图内小字是否需要继续放大、失败成本是否舒服、00 是否具有情感价值，均留给真实试玩回答。

不额外增加 P13 或奖励系统来替代反馈。工程验收完成后，按试玩记录中的具体卡点回到相应关卡修订，再复跑受影响的检查。
